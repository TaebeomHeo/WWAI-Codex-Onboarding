# 실습 3: Gemini와 함께 나만의 작업 스타일 만들기 (`gemini.md`)

이 실습에서는 Gemini CLI가 당신의 작업 스타일을 이해하고, 더 효율적으로 협업할 수 있도록 돕는 `gemini.md` 파일에 대해 배웁니다.

## 목표

- `gemini.md` 파일의 역할과 중요성을 이해합니다.
- `gemini.md` 파일을 작성하는 두 가지 주요 방법을 배웁니다.
- Gemini에게 현재까지의 작업 스타일을 분석하여 `gemini.md` 파일을 생성하도록 요청하는 방법을 익힙니다.

## `gemini.md`란 무엇인가요?

`gemini.md` 파일은 프로젝트의 루트 디렉토리에 위치하며, Gemini CLI가 작업을 수행할 때 따라야 할 규칙과 스타일 가이드를 정의하는 파일입니다. 이 파일을 통해 당신은 Gemini에게 다음과 같은 사항들을 알려줄 수 있습니다.

- 선호하는 프로그래밍 언어 및 라이브러리
- 코드 포맷팅 스타일 (예: 들여쓰기, 세미콜론 사용 여부)
- 커밋 메시지 형식
- 파일 구조 규칙
- 기타 프로젝트 관련 선호 사항

`gemini.md`를 사용하면 매번 같은 지시를 반복할 필요 없이, Gemini가 당신의 스타일에 맞는 결과물을 일관되게 생성하도록 만들 수 있습니다.

## `gemini.md` 작성 방법

`gemini.md` 파일을 만드는 방법은 크게 두 가지가 있습니다.

### 방법 1: 프로젝트 시작 시점에 직접 정의하기

프로젝트를 새로 시작할 때, 당신이 선호하는 작업 방식을 `gemini.md` 파일에 직접 작성할 수 있습니다.

**예시 `gemini.md` 파일:**

```markdown
# Gemini 스타일 가이드

## 일반
- 모든 텍스트 파일은 UTF-8로 인코딩합니다.
- 파일 끝에는 항상 한 줄의 공백을 둡니다.

## Python
- `pandas`와 `openpyxl` 라이브러리를 사용하여 Excel 파일을 처리합니다.
- 코드는 PEP 8 스타일 가이드를 따릅니다.
- 새로운 스크립트는 `scripts/` 디렉토리에 저장합니다.

## 커밋 메시지
- 형식: `타입: 제목` (예: `feat: 새로운 기능 추가`)
- 제목은 50자 이내로 간결하게 작성합니다.
```

### 방법 2: Gemini에게 지금까지의 작업 스타일 분석 요청하기

이미 프로젝트를 어느 정도 진행했다면, Gemini가 현재까지의 작업 내역을 분석하여 당신의 스타일을 파악하고 `gemini.md` 파일을 생성하도록 요청할 수 있습니다. 이는 당신이 미처 인지하지 못했던 자신만의 작업 패턴을 발견하는 데에도 도움이 됩니다.

## 지침

이제 Gemini에게 이 `gemini-onboarding` 프로젝트에서 우리가 함께 작업한 스타일을 기반으로 `gemini.md` 파일을 만들어달라고 요청해봅시다.

다음과 같은 프롬프트를 사용해 보세요.

> "지금까지 우리가 함께 작업한 내용을 바탕으로, 이 `gemini-onboarding` 프로젝트를 위한 `gemini.md` 파일을 만들어줘. 파일에는 우리가 사용한 언어, 라이브러리, 파일 구조, 그리고 일반적인 작업 패턴에 대한 내용이 포함되어야 해."

Gemini가 생성한 `gemini.md` 파일의 내용을 확인하고, 당신의 생각과 다른 부분이 있다면 직접 수정하여 완성해보세요.

이제 Gemini CLI에게 작업을 지시하여 이 실습을 완료해보세요!
