# 실습 3: 작업의 시스템화 (Instruction File)

## 목표

매번 긴 프롬프트를 입력하는 대신, **재사용 가능한 지시문 파일(Instruction File)**을 만들어 반복적인 업무를 자동화하는 방법을 배웁니다.

## 왜 필요한가요?

"Jira 보고해줘"라고 매번 말할 때마다 결과가 달라진다면 신뢰할 수 없습니다.
입력(Input), 처리 과정(Process), 출력(Output)을 명세서처럼 미리 정의해두면, 언제나 일관된 고품질의 결과를 얻을 수 있습니다.

## 단계 1: 템플릿 탐색하기

우리가 미리 준비한 예제 템플릿을 살펴봅시다.

1.  파일 열기: `antigravity-onboarding/templates/instruction-email-report.md`
2.  **구조 확인**:
    - **Goal**: 무엇을 하는 에이전트인가?
    - **Inputs**: 어떤 정보를 봐야 하는가?
    - **Process**: 어떤 순서로 생각해야 하는가?
    - **Output Format**: 최종 결과물은 어떤 모양이어야 하는가?

## 단계 2: 나만의 지시문 만들기

여러분의 실제 업무에 맞춰 템플릿을 복사해서 수정해봅시다.

1.  `instruction-email-report.md` 파일을 복사하여 `my-weekly-report.md`를 만드세요.
2.  여러분의 팀 스타일이나 특정 요구사항을 반영하여 내용을 수정하세요.
    - 예: "Tone & Manner"를 "친근하고 부드럽게"로 변경
    - 예: "Output Format"에 "다음 주 계획" 섹션 추가

## 단계 3: 지시문 실행하기 (Action)

이제 에이전트에게 **"이 명세서대로 일해"**라고 시켜봅시다.

1.  **Context 열기**: 실습 2와 동일하게 브라우저에 Jira와 Webmail을 띄웁니다.
2.  **지시하기**:

    ```text
    [파일] my-weekly-report.md

    위 규칙(지시문 파일)을 읽고, 현재 열려있는 브라우저 탭들을 참고해서 보고 메일을 작성해줘.
    ```

## 핵심 요약

- 반복되는 업무는 **프롬프트**가 아닌 **파일**로 관리하세요.
- **Instruction File**은 에이전트에게 전하는 "작업 표준 명세서"입니다.
- 이 파일을 팀원들과 공유하면, 누구나 똑같은 품질의 업무 보고를 할 수 있습니다 (SOP의 자동화).
