# 실습 4: 긴 맥락 관리 (Email History)

## 목표

수십 통이 오고 간 긴 이메일 스레드나 채팅 히스토리를 에이전트가 놓치지 않고 관리하는 기술을 익힙니다.
**"Summary-Driven Workflow"**를 통해 컨텍스트 윈도우 한계를 극복하고 중요 정보를 유지하는 방법을 배웁니다.

## 문제 상황

프로젝트 진행 중 발생한 긴 논의(이메일 30통, Slack 스레드 100개)가 있습니다.

- "지난달에 A님이 언급한 보안 이슈가 뭐였지?"
- "그래서 결론적으로 지금 우리가 해야 할 작업이 뭐지?"

이 모든 텍스트를 매번 에이전트에게 다 읽으라고 하기엔 비효율적이고, 중요한 정보가 희석될 수 있습니다.

## 해결 전략: `history.md` 운용하기

에이전트에게 "기억을 외부에 기록"하도록 시키는 전략입니다.

1.  **Raw Data**: 긴 이메일 원문
2.  **Processing**: 에이전트가 핵심만 요약
3.  **Storage**: `history.md` 파일에 누적 기록
4.  **Action**: 다음 작업 시에는 원문 대신 `history.md`를 참고

## 실습 단계

### 1단계: 히스토리 파일 생성

먼저 에이전트에게 긴 대화 내용을 요약해서 파일로 저장하라고 시킵니다.

> **Context**: (긴 이메일 스레드가 열려있는 브라우저 탭)
>
> **Prompt**:
> "현재 열려있는 이메일 스레드를 읽고, 주요 의사결정 사항과 Action Item 위주로 요약해서 `project_history.md` 파일에 저장해줘. 날짜별로 정리해."

### 2단계: 최신 업무 처리

이제 새로운 이메일이 왔을 때, 전체 스레드를 다시 읽는 대신 `project_history.md`를 참고하여 답변합니다.

> **Context**: (방금 도착한 새로운 이메일 1통)
>
> **Prompt**:
> "새로 온 이메일을 읽고 답장 초안을 작성해줘.
> 단, 과거 히스토리는 `project_history.md` 파일을 참고해서 문맥을 파악해.
> 우리 팀이 지난주에 합의했던 'API 스펙' 내용과 모순되지 않도록 주의해줘."

### 3단계: 히스토리 업데이트 (Loop)

업무 처리가 끝나면, 새로운 내용을 다시 히스토리에 반영합니다.

> **Prompt**:
> "방금 수신한 메일과 내 답장 내용에서 중요한 업데이트 사항이 있다면, `project_history.md` 파일 끝에 추가해줘."

## 핵심 요약

- **State Management**: 에이전트는 상태(State)가 없습니다. 파일 시스템(`history.md`)을 에이전트의 "장기 기억"으로 활용하세요.
- **Compression**: 원문(Raw)을 그대로 두지 말고, "요약(Summary)" 형태로 압축하여 관리하면 효율적입니다.
